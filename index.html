01 / ESP32 · SENSOR SYSTEMS · EMBEDDED C++IN DEVELOPMENT

IoT Food Spoilage Monitoring & Alerting System

An ESP32-based experimental monitoring prototype that samples temperature, relative humidity and an MQ-135 gas-sensor response. Firmware updates the SSD1306 OLED and publishes JSON telemetry over Wi-Fi/MQTT for a browser dashboard, with a local alert output in the hardware prototype.

ESP32 WROOMEmbedded C++DHT22MQ-135ADCSSD1306 OLEDI²CWi-FiMQTT

System architecture

  • DHT22: temperature and relative humidity
  • MQ-135: analogue gas-sensor response
  • ESP32: sampling, application logic and Wi-Fi
  • MQTT: JSON telemetry to browser dashboard
  • SSD1306: I²C display; buzzer: local alert output

Prototype pin notes

  • DHT22 data → GPIO 4
  • MQ-135 analogue → GPIO 35 (conditioned input)
  • OLED SDA / SCL → GPIO 18 / 19
  • OLED address → 0x3C
  • Buzzer control → GPIO 25
  • MQ sensor supply → VIN / 5 V (module-dependent)

Engineering challenge: MQ-135 readings are cross-sensitive and affected by warm-up, humidity, temperature and ageing. The raw ADC value is not a calibrated gas concentration. Current work is focused on baseline capture, repeatability and logging environmental context — not a validated spoilage classifier.

Next validation steps: characterize warm-up and drift, collect repeated samples under documented conditions, correlate gas response with DHT22 readings, and only then evaluate whether a labelled dataset supports a model.

06 / Engineering notebook

Notes from the bench.

Short technical explainers on the concepts behind embedded firmware. Open a note to explore the key idea.

NOTE 01 / DATA ACQUISITION

ADC & signal acquisition

Turning a continuous voltage into a digital code.

Open notebook entry

An ideal N-bit ADC has 2^N quantization codes. For a 12-bit range from 0 to 3.3 V, an approximate conversion is V = code × 3.3 / 4095. Real measurements also depend on reference accuracy, input impedance, noise, attenuation and ADC non-linearity.

NOTE 02 / SERIAL BUSES

UART vs I²C vs SPI

Three interfaces, different timing and wiring trade-offs.

Open notebook entry

UART is asynchronous point-to-point serial using agreed framing and baud rate. I²C uses SDA/SCL with addressed devices and open-drain signalling. SPI uses a clock, data lines and typically a chip-select per peripheral; it is often faster but uses more pins.

NOTE 03 / TIMING

PWM generation

Control average delivered power with a timed digital output.

Open notebook entry

PWM alternates between logic levels. Duty cycle is the fraction of a period spent HIGH. At a fixed supply, the average ideal voltage is approximately duty × supply voltage for a simple low-pass/load interpretation. Frequency and load characteristics matter.

NOTE 04 / EVENTS

Interrupts

Responding to events without continuously polling.

Open notebook entry

An interrupt service routine should be short and predictable: capture the event, update minimal state, and defer heavier work to the main loop or a task. Shared data needs careful synchronization and platform-specific ISR-safe APIs.

NOTE 05 / LANGUAGE

Embedded C

Explicit control over memory, data and hardware interfaces.

Open notebook entry

Embedded C commonly uses fixed-width integer types, explicit peripheral interfaces, bounded buffers and careful error handling. Volatile is relevant to objects changed outside normal program flow, such as memory-mapped registers, but it is not a general concurrency primitive.

NOTE 06 / SCHEDULING

FreeRTOS task scheduling

Split firmware into concurrent, cooperating activities.

Open notebook entry

Tasks have priorities and states; a scheduler selects runnable work. Queues, semaphores and task notifications support coordination. Timing, stack sizing, priority inversion and blocking behaviour should be considered in system design.

NOTE 07 / ENERGY

Battery Management Systems

Monitor and protect cells and packs.

Open notebook entry

A BMS may monitor cell voltage, pack current and temperature, estimate state of charge/health, balance cells and control protection switches. Safe thresholds and algorithms depend on cell chemistry, pack design and validated requirements.

NOTE 08 / VEHICLE NETWORKS

CAN communication

Robust message-based communication on shared buses.

Open notebook entry

CAN uses message identifiers and arbitration rather than node addresses in the usual sense. Differential signalling, termination and bit timing are important. Higher-layer protocols define additional conventions for diagnostics and device profiles.

NOTE 09 / RTL CONTROL

Moore FSM design

Model control behaviour as states, transitions and registered outputs.

Open notebook entry

In a Moore machine, outputs depend on the current state. A clean RTL implementation separates state registers, next-state logic and output decoding. Reset behaviour, illegal-state recovery, timer handshakes and transition coverage should be considered and verified in a self-checking testbench.

NOTE 10 / PROCESSOR ARCHITECTURE

Single-cycle RISC-V datapath

Trace an instruction through a modular processor datapath.

Open notebook entry

A single-cycle core completes fetch, decode, execute, memory access and write-back within one clock cycle. The control unit decodes the instruction, the ALU performs arithmetic or address calculations, and multiplexers select the next PC and write-back value. The design is easy to reason about, but the clock period must accommodate the longest instruction path.
